# Three-layer architecture: shared/c logic, shared/components rendering, per-watchface windows

Pebble's own "Modular App Architecture" guide recommends splitting apps into `.h`/`.c` modules with static internals, custom `Layer` subclasses as reusable rendering components (via `layer_get_data()` + `layer_set_update_proc()`), and thin per-window orchestration. We adopt this as three explicit tiers: `shared/c/` for pure logic with no Pebble SDK dependency (already decided in ADR-0003), `shared/components/` for reusable custom-Layer rendering components (e.g. a time/date display layer, a battery indicator layer) that do depend on the Pebble SDK but not on any single watchface, and each watchface's own `windows/` module that wires components and logic together. We chose to stand up `shared/components/` now, ahead of a second watchface actually existing, anticipating that most watchfaces in this repo will reuse the same handful of rendering components — accepting the risk of designing an interface before a second real consumer exists.
